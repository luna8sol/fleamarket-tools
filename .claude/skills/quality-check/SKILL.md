# 品質チェック

コマンドと現状の正本は [CLAUDE.md の「検証」](../../../CLAUDE.md)。ここには**回し方**を書く。

## 前提: このリポジトリに自動テストは無い

`package.json` に `test` スクリプトは無く、テストフレームワークも依存に入っていない。「テストを回す」は**型チェック・ビルド・静的解析を回す**ことを指す。**実行していないテストの結果を報告に書かない。**

## 原則: 全部回す

パッケージはルート 1 つだけ（モノレポではない）。**全部回しても合計 20 秒程度**なので、影響範囲を考える時間のほうが高くつく。絞り込みの判断はしない。

```bash
npm run typecheck       # 型チェック（約 5 秒 / 通過するのが正常）
npm run build           # ビルド（約 6 秒 / 通過するのが正常）
npm run lint            # 静的解析（約 6 秒 / 通過するのが正常）
npm run format:check    # フォーマット（約 3 秒 / 通過するのが正常）
```

すべてリポジトリルートで実行する。**`cd` で移動が必要な場合はサブシェル `(cd dir && ...)` にして持ち越さない。**

## 落ちたときの判断

- **4 つとも通るのが正常。落ちたらそれは自分の変更のせい。** 直してから再実行する。**通っている状態を壊さないこと。**
- `npm run format:check` が落ちたら、触ったファイルだけ `npx prettier --write <そのファイル>` で直す。**`npm run format` でリポジトリ全体を一括整形しない**（差分が膨れて本来の変更が埋もれる）。
- **`format:check` が全ファイルで落ちたら、まず改行コードを疑う。** 改行は [.gitattributes](../../../.gitattributes) で LF に固定してある。作業ツリーが CRLF になっていると、中身が整形済みでも全ファイルが差分として報告される。確認は `git ls-files --eol <パス>` で、`w/` が `lf` かどうか。
- **`npm run build` が通っても、動作確認にはならない。** 自動テストが無いので、挙動を変えたなら Chrome に読み込んで確かめる（`local-setup` スキル）。確かめていないなら**報告に「未検証」と書く**。

## 絞り込む判断をするとき（ドキュメントだけ触った場合など）

絞ってよいのは**ドキュメントと開発ツール設定だけを触ったとき**に限る。ルート直下の `package.json` / `package-lock.json` / `tsconfig.json` / `eslint.config.js` / `webpack.config.js` / `manifest.json` は全体に効くので、触ったら**回す側**に入れる。

変更パスは**この 3 つとも**集める:

```bash
git diff --name-only --no-renames develop...HEAD      # このブランチが入れたコミット済みの変更
git diff --name-only --no-renames HEAD                # 未コミットの変更（ステージ済み含む）
git ls-files --others --exclude-standard              # 未追跡の新規ファイル
```

- **`...`（3 点）を使う。** `develop..HEAD`（2 点）にすると、`develop` 側が進んでいるときに相手側の変更まで差分に出る。3 点なら**分岐点からこのブランチが入れた変更だけ**になる。
- **比較元を最新にしてから実行する。** `develop` は `origin/develop` と同期しているので、`git fetch origin develop` のあと `git log develop..origin/develop` が空か確かめる。空でなければ先に `git switch develop && git pull --ff-only` で追いつかせる（手元の `develop` が古いまま比較すると、差分に相手側の変更が混ざる）。
- **`--no-renames` を省かない。** 既定ではリネームが畳まれて移動後のパスしか出ず、移動元のディレクトリを対象から落とす。
- **`| sort -u` のような 1 本のパイプにまとめない。** どれかが失敗してもパイプ全体は成功し、「変更なし」に見えたまま未検証で進む。3 回別々に実行して、それぞれの結果を見る。
- **`git status --porcelain` は使わない。** リネームが `R old -> new` の 1 行になりパスとして取り出せない。

## CI

CI は存在しない（`.github/workflows/` 無し）。CI を追加・変更したら、**そのワークフローが実行するコマンドを手元でも 1 度通す**。

## 結果の報告

- **失敗したままコミットしない。** 直してから再実行する。
- **実行したコマンドと結果を控えて、報告にそのまま書く。**

```
npm run typecheck     → 通過
npm run build         → 通過
npm run lint          → 通過
npm run format:check  → 通過
テスト                → 未実行（このリポジトリにテストは存在しない）
Chrome での動作確認   → 未実施
```

- **実行していないコマンドの結果を書かない。未検証の項目は未検証と明記する**（書かない方が減点）。
