# 品質チェック

コマンドと現状の正本は [CLAUDE.md の「検証」](../../../CLAUDE.md)。ここには**回し方**を書く。

## 前提: このリポジトリに自動テストは無い

`package.json` に `test` スクリプトは無く、テストフレームワークも依存に入っていない。「テストを回す」は**型チェック・ビルド・静的解析を回す**ことを指す。**実行していないテストの結果を報告に書かない。**

## 原則: 全部回す

パッケージはルート 1 つだけ（モノレポではない）。**全部回しても合計 15 秒程度**なので、影響範囲を考える時間のほうが高くつく。絞り込みの判断はしない。

```bash
npx tsc --noEmit        # 型チェック（約 5 秒 / 通過するのが正常）
npm run build           # ビルド（約 3.5 秒 / 通過するのが正常）
npm run lint            # 静的解析（約 5 秒 / 通過するのが正常）
npm run format:check    # フォーマット（約 3 秒 / 既存コードが未通過で落ちる）
```

すべてリポジトリルートで実行する。**`cd` で移動が必要な場合はサブシェル `(cd dir && ...)` にして持ち越さない。**

## 落ちたときの判断

- **`npx tsc --noEmit` / `npm run build` / `npm run lint` が落ちたら、それは自分の変更のせい。** 直してから再実行する。
  - `npm run lint` は `main` では 17 errors あったが `develop` で解消済み。**通っている状態を壊さないこと。**
- **`npm run format:check` だけは元から落ちる**（29 ファイルに差分）。落ちたこと自体は異常ではない。**自分が触ったファイルが指摘に増えていないか**で判断する。
  ```bash
  npm run format:check 2>&1 | grep '<自分が触ったファイルのパス>'
  ```
  増えていれば `npx prettier --write <そのファイル>` で直す。**`npm run format` でリポジトリ全体を一括整形しない**（29 ファイル分の差分が本来の変更を埋める）。
- **型チェックに `npm run build:tsc` を使わない。** `--noEmit` が無く `dist/` を汚す。

## 絞り込む判断をするとき（ドキュメントだけ触った場合など）

絞ってよいのは**ドキュメントと開発ツール設定だけを触ったとき**に限る。ルート直下の `package.json` / `package-lock.json` / `tsconfig.json` / `eslint.config.js` / `webpack.config.js` は全体に効くので、触ったら**回す側**に入れる。

変更パスは**この 3 つとも**集める:

```bash
git diff --name-only --no-renames HEAD                    # 未コミットの変更（ステージ済み含む）
git diff --name-only --no-renames <直前のコミット>..HEAD  # 今回の作業でコミット済みの変更
git ls-files --others --exclude-standard                  # 未追跡の新規ファイル
```

- **`--no-renames` を省かない。** 既定ではリネームが畳まれて移動後のパスしか出ず、移動元のディレクトリを対象から落とす。
- **`| sort -u` のような 1 本のパイプにまとめない。** どれかが失敗してもパイプ全体は成功し、「変更なし」に見えたまま未検証で進む。3 回別々に実行して、それぞれの結果を見る。
- **`git status --porcelain` は使わない。** リネームが `R old -> new` の 1 行になりパスとして取り出せない。

## CI

CI は存在しない（`.github/workflows/` 無し）。CI を追加・変更したら、**そのワークフローが実行するコマンドを手元でも 1 度通す**。

## 結果の報告

- **失敗したままコミットしない。** 直してから再実行する（元から落ちている `format:check` を除く）。
- **実行したコマンドと結果を控えて、報告にそのまま書く。**

```
npx tsc --noEmit      → 通過
npm run build         → 通過
npm run lint          → 通過
npm run format:check  → 29 ファイルに差分（すべて既存コード。今回の変更分は 0）
テスト                → 未実行（このリポジトリにテストは存在しない）
```

- **実行していないコマンドの結果を書かない。未検証の項目は未検証と明記する**（書かない方が減点）。
