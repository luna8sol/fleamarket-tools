# Mercari Draft Publisher

メルカリの下書き商品を効率的に出品するための Chrome 拡張機能です。

## 機能

- 下書き商品の一括出品（実行前に件数・処理順の商品名を出して確認）
- 出品済み商品の一括再出品（同上）
- 出品済み商品の一括削除（実行前に件数と商品名を出して確認）
- 出品済み商品の説明文の一括置換（確定版と原本の JSON を読み込み、照合が通った商品だけ保存）
- 再出品で開いた出品フォームを元商品と比較し、問題なければ下書きに保存
- 選択順の管理と視覚的表示
- 商品画像と入力済みの商品情報をもとにした AI 商品説明文の生成（Claude API）
- ライト / ダークモード対応の UI（OS の配色設定に追従。メルカリ本体と同じ条件で切り替わる）

## セットアップ

```bash
npm install
npm run build
```

Chrome の拡張機能管理ページ（`chrome://extensions`）を開き、「デベロッパーモード」をオンにして「パッケージ化されていない拡張機能を読み込む」から**リポジトリルート**（`manifest.json` があるディレクトリ）を選択してください。`manifest.json` がそこから `dist/content.js` を参照するため、`dist` ディレクトリ自体を選ぶと読み込めません。

### Claude API キーの設定（AI 説明文生成を使う場合のみ）

拡張機能の「詳細」→「拡張機能のオプション」から設定画面を開き、[Claude Console](https://console.anthropic.com/settings/keys) で発行した API キーを保存してください。キーはこのブラウザの拡張機能ストレージにのみ保存され、Claude API 以外には送信されません。一括出品・一括再出品はキーなしで動きます。

## 再出品後の自動下書き保存

再出品ボタンを押すと別タブで開く出品フォームの内容を、元商品（商品名・販売価格・
商品の説明・カテゴリー・商品の状態・配送設定・商品の特徴・画像枚数）と比較します。差分があれば
元商品の値へ自動で書き戻し、それでも解消できない差分が残る場合は保存せずに中断して
通知します。詳細は [アーキテクチャ詳細](docs/ARCHITECTURE.md) を参照してください。

**押すのは「下書きに保存する」だけで、「出品する」は押しません。** 流し込みが途中の内容でも
世に出てしまい、取り消せないためです。公開は下書き一覧からの一括出品で、人が内容を見てから
行ってください。

比較の基準は、元商品の**編集フォーム**（`/sell/edit/{itemId}`）を同一オリジンの隠し
iframe で読み込んで取得します。メルカリは Next.js App Router に移行済みで、商品ページの
HTML から商品データを取り出すことはできません。編集フォームは再出品フォームと同じ部品
でできているため、フォーム対フォームで表現が揃います。**この iframe を保存することは
ありません。**

設定は拡張機能のポップアップから行います。

| 設定 | 既定値 | 説明 |
|------|-------|------|
| 元商品と比較して問題なければ下書きに保存する | ON | 自動下書き保存の有効 / 無効 |
| ドライラン（比較のみ・下書き保存ボタンは押さない） | ON | 比較と差分修正までを行い、下書き保存ボタンは押さない |

> **初回は必ずドライランのまま動作を確認してください。**
> `src/content/infra/constants.ts` の `SELL_FORM_FIELDS` に定義したセレクタは
> 2026-09-17 時点の実地調査に基づくもので、メルカリ側の変更で外れることがあります。
> デバッグモードを有効にすると、出品フォームのコンソールに各項目の解決状況が
> 出力されます。すべての項目が `resolved: true` になっていることを確認してから、
> ドライランを解除してください。

## 説明文の一括置換

出品中の商品の説明欄だけを、あらかじめ用意した確定版の本文へ 1 件ずつ置き換えて保存します。
出品中一覧（`/mypage/listings`）の一括操作バーにある「説明文を一括置換」から開きます。

1. **確定版 JSON** と **原本 JSON** を選ぶ。どちらも `[{ "id", "name", "desc" }]` の配列で、
   `id` は `m` + 数字の商品ID、`desc` が本文。原本は取得時点の本文で、置き換える前の照合に使う
2. 「読み込む」を押すと、対象件数・記録上すでに適用済みの件数・対象外（原本なし・1000 字超）・
   これから処理する件数が表示される。**この時点では 1 件も保存しない**
3. 1 件ごとの待機秒数を必要なら変える（既定は `src/content/infra/constants.ts` の
   `DESCRIPTION_REPLACE_WAIT_BASE_MS`。これに数秒のランダム分が足される）
4. 「開始（確認あり）」を押し、件数を確認して承諾すると 1 件ずつ処理が始まる
5. 「中断」でいつでも止められる。処理中の 1 件は、保存ボタンを押す前なら保存せずに止まる
6. 「結果を出力（JSON）」で処理記録をダウンロードできる

各商品は、編集ページの商品名がデータと一致し、説明欄の現在値が原本と一致するときだけ
書き換えます。書き込み後の値が確定版と一字一句一致することを文字数とハッシュで確認してから
「変更する」を押し、保存後の商品ページの本文でもう一度照合します。照合が通らない商品は
保存せずスキップとして記録します。**削除ボタンには触れず、説明欄以外は変更しません。**

処理記録は商品IDごとに拡張機能ストレージに残り、次の実行では成功・適用済みの商品を
対象から外します（記録の確定版と今回の確定版が同じ本文のときだけ。確定版を改訂すれば
改めて対象になります）。中断して再開しても同じ商品を二重に保存することはありません。

## 開発コマンド

| コマンド | 説明 |
|---------|------|
| `npm run build` | 開発用ビルド |
| `npm run build:prod` | 本番用ビルド（最適化・圧縮あり） |
| `npm run build:dev` | 開発用ビルド（ソースマップ付き） |
| `npm run lint` | ESLint で静的解析 |
| `npm run lint:fix` | ESLint で自動修正 |
| `npm run format` | Prettier でフォーマット |
| `npm run format:check` | Prettier でフォーマット差分チェック |
| `npm run clean` | dist ディレクトリを削除 |
