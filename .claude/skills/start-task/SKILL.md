# タスクに着手する

規約の正本は [CLAUDE.md](../../../CLAUDE.md)。ここには**手順**だけを書く。

## 1. 読む（推測で書き始めない）

- **CLAUDE.md の「着手前に読むもの」索引にある一次資料と、該当コードを直接読む。** 索引に無い領域なら、該当ディレクトリのコードを読んでから始める。
- **文書とコードが食い違ったらコードが正。** `docs/ARCHITECTURE.md` と `README.md` には既知のズレがある（CLAUDE.md に一覧がある）。古い記述を見つけたらその場で直す。
- **過去のメモや会話に書かれた構成図を信用しない。** 廃止された仕組みがそのまま残っていることがある。実例:
  - `scripts/content.js` / `scripts/popup.js` は git 管理下に残っているが、現在のビルドでは更新されず `manifest.json` からも参照されていない
  - `docs/ARCHITECTURE.md` は `selection.ts` / `observer.ts` / `bulk-bar.ts` を挙げているが、いずれも現在は存在しない

  必ず現物のファイルで確かめる。
- **確かめていないことを断定しない。** メルカリ側の DOM・Chrome 拡張 API の制約は、実際に動かすか公式ドキュメントで確認するまで「要検証」と明記する。「たぶん動く」で設計を進めない。

## 2. スコープを決める

- **依頼されたスコープを勝手に広げない。** 作業中に見つけた別の問題は、直さずに書き出して報告する。**1 コミットは 1 つの目的に絞る。**
  - このリポジトリでは `npm run format:check` が元から落ちている。**ついでに直さない。** 差分が膨れて本来の変更が埋もれる。
- **方針決めと実装を 1 つの作業単位に混ぜない。** 方針が定まっていないものは、**決めて書き残すまでを 1 単位**にし、実装は別にする。決まっていない状態で書いた実装は、方針が動いたときにまるごと捨てることになる。
- **方針を変える判断をしたら理由を残す。** 選ばなかった案とその理由まで書く。

## 3. 実装する

CLAUDE.md の「最重要方針」に照らしながら書く。とくにこのリポジトリでは:

- 一括出品・一括再出品は**取り消せない実操作**。対象の絞り込み条件と件数のガードを先に決める。
- セレクタとページ判定は**メルカリ側の変更で壊れる**。新しいセレクタは `src/content/infra/constants.ts` に置き、要素が見つからないときに黙って続行しないこと。

## 4. 既定の停止点はコミット

1. **品質チェックを通す** → `quality-check` スキル
2. **セルフレビューする** → `self-review` スキル
3. **コミットする** → `commit` スキル
4. **やったことを数行で報告して終える**

コミットまでで止める。**ブランチのマージや push は、明示的に頼まれない限りやらない**（ブランチ運用は [CONTRIBUTING.md](../../../CONTRIBUTING.md) にあるが、その実行はこのスキルの範囲外）。

**逆方向の指示を尊重する。** 「コミットしないで」「品質チェックだけ」「調べるだけ」と言われたら、そこで止めて残りをやらない。
